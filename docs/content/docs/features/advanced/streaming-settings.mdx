Two Settings-dialog panels control how elevation data gets from a COG into the renderer, and what the browser keeps between sessions. Neither affects *what* is computed — only how it's fetched, how precisely it's encoded, and whether it survives a reload.

## Streaming Settings

### COG Streaming: MapLibre vs Titiler

Two engines can turn a Cloud-Optimized GeoTIFF into map tiles:

- **MapLibre** (default) — [@geomatico/maplibre-cog-protocol](https://github.com/geomatico/maplibre-cog-protocol) reads the COG directly in the browser via HTTP range requests: no middleware, faster, and no shared-server load. The COG must be reachable with CORS enabled and already in Web Mercator (see [BYOD](/features/byod) for the `gdalwarp`/`gdal_translate` fix-ups) — a CORS-blocked file is the usual reason to flip this switch. When a tile is upsampled from a coarser overview, this reader resamples it bilinearly (a patched version of the geomatico reader), so a 10 cm DSM no longer shows nearest-neighbour blocks between overview levels. The source is declared to MapLibre by its `cog://` URL alone, so the protocol's own TileJSON sets the max zoom to the file's finest level and MapLibre stretches that last tile past it, rather than asking the protocol for finer tiles it would have to upsample (the fix [Oscar Fonts](https://github.com/geomatico/maplibre-cog-protocol/issues/56#issuecomment-6285706300) pointed out). A **Max Zoom** typed under the source's Advanced fields still overrides it.
- **Titiler** — a [Titiler](https://developmentseed.org/titiler/) middleware instance fetches the remote COG server-side and streams standard TMS tiles back. More tolerant (it reprojects and proxies CORS-less files), at the cost of an extra hop and server load. [Contour Lines](/features/visualization-modes) always use this path — they can't read a local file or raw COG directly.

The **Titiler Endpoint** field at the bottom of the panel points both the streaming fallback and the export path at your own instance (default `https://titiler.xyz`); it travels with a [Project export](/features/index) so a shared project keeps working against the same server.

### G-LiHT proxy

In **Settings → API Keys** since 2026-11-25 (it was here, as G-LiHT address), its explanation on hover. Where NASA G-LiHT's KMZs are read from (the coverage popup's **Use as overlay** and the Kiuic library entries). By default the tile service on this computer, `http://localhost:3400/proxy/gliht`; when it does not answer, NASA's host is tried directly and a message says so (the arrow next to the label puts the default back). Empty: NASA's host only, which sends no CORS header, so only with a CORS-unblocking browser extension. Or another [tile service](/dev/tile-service#cors-proxy-for-nasa-g-liht)'s `<server>/proxy/gliht`, or any CORS proxy written with `{url}` where the address goes. Kept in this browser only. See [NASA G-LiHT](/dev/g-liht).

### High-Precision Elevation Quantization

Visible only on the MapLibre/COG-protocol path. Elevation tiles are quantized into an RGB packing — [Mapbox Terrain-RGB](https://docs.mapbox.com/data/tilesets/reference/mapbox-terrain-rgb-v1/) steps at **10 cm**, [Terrarium](https://github.com/tilezen/joerd/blob/master/docs/formats.md#terrarium) at **~3.9 mm**. This switch re-encodes streamed COGs as Terrarium instead of Terrain-RGB: slower streaming, but flat or gently-sloped surfaces stop banding in the derivative modes (slope, curvature, hillshade on near-flat terrain make 10 cm steps very visible). The [terrain-analysis pipeline](/dev/terrain-analysis-pipeline) page covers why each visualization mode picks the packing it does.

### DTM Export without Titiler

Client-side GeoTIFF export: the browser range-reads and mosaics tiles/COGs directly, bypassing Titiler's server-side size cap. Works for COG, Terrain-RGB, and Terrarium sources — including a [local COG file](/features/byod#local-offline-cog-terrain-sources) that no server could reach.

### HiDPI Google Earth Tiles

On by default. [Google Earth Historical](/dev/ge-historical) tiles come from Google's plate-carrée grid, where a tile spans as many degrees of latitude as of longitude, while a Web Mercator tile spans cos(latitude) times fewer: built from the same level, a tile is exact across and stretched down by 1.5× at Paris, 2× at 60°. This switch builds each tile from one level finer into a 512 px image, a downsample everywhere below 60° and the 2× image a HiDPI screen can show. Four times the Keyhole fetches; turn it off on a slow connection. [Which date is drawn as you zoom](/dev/ge-historical#which-date-is-drawn-as-you-zoom) covers the other reason a Google Earth view can look soft, a date not listed at that level.

### Cache Computed Viz-Mode Tiles

Keeps finished computed tiles (Terrain Analysis, detectors, …) in an in-memory cache of up to ~96 MB, so toggling a mode off and back on redisplays instantly instead of recomputing every visible tile. Costs memory, saves recompute — turn it off on low-RAM machines.

### Contours in workers

Not a setting: always on (the switch was removed on 2026-11-18). Contour lines (absolute, LRM and the iso-line) are generated in MapLibre's own background workers for every terrain source type, so panning stays smooth while they are traced. DEM tiles are still read on the main thread when the source uses one of the app's own protocols (VRT, LERC, a DEM difference, LRM). A plain web tile source is read in the worker too. A local COG file uses its own worker. MapLibre runs up to four of these workers (cores minus 2; its own default is one on Chrome, Edge and Firefox), so a screenful of contour tiles lands about 30% sooner.

### Native Terrain Draping

On by default. The live (fast) Phong and Matcap shading is draped on 3D terrain by MapLibre itself, through its experimental `renderToTerrainTile` hook: the shading is drawn into MapLibre's terrain tiles only when something changes, so panning costs almost nothing. Turn it off to go back to the previous drape, where the app builds its own terrain mesh every frame, if the shading looks wrong or a future MapLibre version changes the hook.

### Raster compute in workers

Not a setting either: always on. Sky View Factor, Openness, Local Dominance and Hard Shadows tiles are computed in a small pool of background workers, up to four tiles at once, instead of on the main thread. There is one pool for the whole page (cores minus 2, at most four workers), shared by every mode and every view: turning on more layers queues more tiles on the same workers, it does not start more of them. The DEM is still read on the main thread, so every terrain source works the same way. The result is identical to the main thread's. Measured with twelve 512 px tiles asked at once: Sky View Factor at radius 8 finished in 0.4 s instead of 1.4 s, Hard Shadows at radius 64 in 0.25 s instead of 0.77 s, and the page missed no frame where it used to freeze for about 100 ms at a time. The same pool size applies to the GeoTIFF decompression of a VRT mosaic read in the browser, also in workers (twelve tiles 0.6 to 0.2 s). Every figure, and how many threads a page uses in all, is on [Tile Performance and Workers](/dev/performance).

## Browser Local Storage Persistence

The app never uploads your local data anywhere; this panel controls what the *browser itself* remembers, backed by [OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) (private per-site storage):

- **Local COG Files** — copies files picked via the [Local COG source type](/features/byod#local-cog-file-built-into-the-app) into OPFS so they don't need re-picking after a reload.
- **Vector Layers (TerraDraw)** — keeps drawn/imported [Drawing](/features/tools#drawing) layers across reloads.

Each category shows a live readout — file/layer count, bytes used, and the site's total browser storage quota — with a **Clear** button to free the space. Everything persisted here (plus bookmarks, custom sources, and settings) can also be bundled into a portable [Project export](/features/index) `.zip`.

Separately from OPFS, plain `localStorage` holds the small stuff — API keys, custom color ramps, collapsed-section state, beta flags — as described in the [architecture overview](/dev/setup).
