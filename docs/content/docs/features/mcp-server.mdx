> Set up the Terrain Viewer MCP server on this computer. Clone https://github.com/Iconem/terrain-viewer, run `pnpm install` at its root and again in its `mcp` folder, then `pnpm build` in `mcp`. Add it to my Claude Desktop configuration file (`claude_desktop_config.json`, under `mcpServers`) as `terrain-viewer`, with the command `node` and the arguments `<path of the clone>/mcp/server.mjs` and `--stdio`. Keep what the file already holds. Tell me when to restart Claude. After the restart I will ask: show me the slope of the terrain around the Matterhorn in 3D.

It needs git, Node 20 or later, pnpm and Google Chrome on the computer. Claude runs the commands and asks before each one unless you allowed them. After the restart, ask in your own words; no tool has to be named.

Save a copy of the file first and keep everything it already holds. Check with `claude mcp list` that the server connects, and tell me to quit and reopen the Claude desktop app.

The image holds its own browser, so only Docker is needed. It is 1.6 GB and renders the pictures without the graphics card, slower than the clone does with your Chrome (about 9 s a picture against a few). To update it: `docker pull` again and restart the apps.

With the clone, both apps start the same server from the same folder, each its own copy, when they open. To update it later: `git pull` in the clone, `pnpm build` in `mcp`, and restart the apps.

The [skill](/features/ai-assistants) teaches an assistant to write a link. The server goes further: the assistant can look things up (where a place is, which datasets cover it, which dated images exist) and the result shows in the conversation.

## What you can ask

- "Show me the slope of the terrain around the Matterhorn in 3D."
- "I am looking for ancient earthworks in the forest of the Veluwe. Which elevation data is best there, and show it so they stand out."
- "Which satellite images exist over Antakya after the February 2023 earthquake? Show the most recent."
- "Compare the surface model and the ground model over Amsterdam."
- "How high is the Matterhorn above Zermatt, and how steep is the line between them?"
- "Give me a GeoTIFF of the elevation around Mont Blanc."

## Tools

| Tool | What it does |
|---|---|
| `open_view` | A place and modes, shown in the conversation as the app itself, with the link that opens it |
| `compare_sources` | One place twice, side by side or as an overlay: two terrain datasets, or the imagery of two dates |
| `geocode` | A place name to coordinates (OpenStreetMap) |
| `datasets_covering` | The terrain datasets of the library that cover a point, finest first, and the imagery catalogs that have something there |
| `catalog_items` | Dated satellite and aerial images and old maps for an area, from the catalogs the [timeline](/features/historical-imagery) reads |
| `imagery_dates` | The capture dates of the built-in dated imagery at a place: Esri Wayback and Google Earth historical |
| `search_stac` | Items of any STAC API or static catalog over an area |
| `elevation` | The height of points, or a profile along a line, on one or several datasets |
| `export_geotiff` | The elevation of an area as a GeoTIFF file (32-bit float, EPSG:3857) |
| `screenshot` | A picture of a view, so the assistant can look at the terrain itself |

`elevation` and `export_geotiff` read tile datasets (Mapterhorn, AWS, Terrarium and Terrain-RGB pyramids). A dataset served as a COG, a WMS or a VRT is read by the app alone: the assistant opens it with `open_view`, and its [Download section](/features/export-and-share) exports it.

## By hand

```bash
git clone https://github.com/Iconem/terrain-viewer
cd terrain-viewer && pnpm install
cd mcp && pnpm install && pnpm build
```

Claude Desktop: Settings, Developer, Edit Config, then restart the app.

```json
{
  "mcpServers": {
    "terrain-viewer": { "command": "node", "args": ["/path/to/terrain-viewer/mcp/server.mjs", "--stdio"] }
  }
}
```

Claude Code:

```bash
claude mcp add terrain-viewer -- node /path/to/terrain-viewer/mcp/server.mjs --stdio
```

claude.ai and ChatGPT reach a server by its address, not on your computer: run `pnpm start` in `mcp` (it listens on `http://localhost:3300/mcp`), put it behind a public HTTPS address, and add that address as a custom connector.

## What shows in the conversation

Two displays, with a button for each:

- **Interactive map**: the app itself, in its [embed layout](/features/embedding), with every mode asked for: pan, zoom, tilt, search, change the modes. The view loads the app's script and styles from its address and runs it in the conversation. Seen working in Claude with a custom connector on 2026-11-21. It is what opens by default.
- **Exact picture**: the same view as a picture, rendered by the server in a few seconds. It shows by itself when the app cannot run in the host (its script refused, or no map after 12 seconds).

**Open in the browser** opens the full app at the place and with the modes the interactive map was left on. The **?** button is for debugging: it says which display was picked and what the host let through.

The interactive map reads only the hosts the server declares: all the hosts of the app's built-in lists (the terrain and raster libraries, the built-in terrain and basemaps, the dated imagery and its catalogs, about 90 hosts). Two kinds cannot be declared in advance and stay blank there: the files a VRT or a STAC item points to on another host, and an address you paste yourself. Claude reads the list when the connector is added, so remove and re-add the connector after an update of the server.

What a strict host may still refuse, from the local test host: WebAssembly (needed by LERC elevation tiles, by the GeoTIFF reader, so by a COG dataset, and by GeoPackage files in the drawing tools) and `eval` (the contour lines' worker failed without it on 2026-11-21). The map, its workers and the computed modes are plain JavaScript. Which of these Claude refuses has not been checked mode by mode.

### Framing the site instead

Where a host allows it, the view frames the site itself, which needs no declared hosts. Claude frames a website inside a conversation only for some connectors: never for a server that runs on your computer, and for a server reached by its address only after you allow the site, in organizations where the feature is on ([Claude's documentation](https://claude.com/docs/connectors/building/mcp-apps/embedded-sites)).

When Claude frames the site depends on how the server reached it:

| Server | Site framed in the conversation |
|---|---|
| In Claude's directory, Verified listing | Shown, when the listing allows the site |
| In Claude's directory, Community listing | Refused |
| Added by its address (custom connector) | Only after you allow the site in the conversation, and only in a limited set of organizations that Anthropic chooses, in the unified chat and Cowork experience |
| Running on your computer | Refused |

No setting in Claude adds a site to an allowed list. Tested on 2026-11-20 with a custom connector on a personal Max plan and on a team with the unified experience on: Claude refused the site both times without asking. That is why the view runs the app itself instead.

### Getting a Verified listing

The only way to the framed site for everyone is a Verified listing in Claude's directory. Not done; what it takes, from Anthropic's pages ([submission](https://claude.com/docs/connectors/building/submission), [review criteria](https://claude.com/docs/connectors/building/review-criteria)), read on 2026-11-20:

- **Where**: `claude.ai/directory/manage`, then Submit new, then MCP connector. Any paid Claude plan can submit.
- **A permanent `https://` address** for the server. A temporary tunnel does not qualify. The server runs a headless Chrome for the pictures, so it needs a container host (the `mcp/Dockerfile`), not a static site or a serverless function.
- **Every tool** with a title and a read-only or destructive hint, a name of 64 characters or fewer, and reading kept apart from writing. The tools already carry titles and hints.
- **Documentation** and a privacy policy address. No sign-in is accepted for public data, which is the case here.
- **Not accepted**: financial transactions, and AI generation of images, video or audio. The `screenshot` tool renders a map and generates nothing, but a reviewer may ask.
- **Review**: a submission is scanned and listed as Community by default, which still refuses the frame. Only some get the human review that leads to Verified, with no stated delay. Escalations: `mcp-review@anthropic.com`. The site to frame has to be named in the listing.

### A permanent address

A directory listing, and a connector that does not change address every two hours, both need the server on a permanent `https://` address. The server answers tool calls with computed results and runs a headless Chrome to render the pictures, which decides where it can live:

| Host | Fits |
|---|---|
| Static site (GitHub Pages) | No: it cannot answer tool calls |
| Serverless functions (Cloudflare Workers, Vercel) | The tools yes; the pictures only with a separate paid browser service and a rewrite of the rendering |
| Container host (Google Cloud Run, Fly.io, Render, Railway) | Yes: runs `mcp/Dockerfile` as it is, Chrome included. It can sleep when unused, at the price of a slower first answer |
| A server you already run with Docker | Yes: the same container, behind your HTTPS reverse proxy |
| MCP hosting services (Cloudflare, Smithery and others) | Built for light servers without a browser |

The plan is the container on an Iconem server, at an address such as `mcp.terrain-viewer.iconem.com`. The image was built and run on a laptop on 2026-11-20 (1.6 GB; the ten tools answer, and a slope view in 3D renders in 9 s without a graphics card); it has not run on a server yet. [`mcp/docker-compose.yml`](https://github.com/Iconem/terrain-viewer/blob/main/mcp/docker-compose.yml) is the stack for Portainer (Stacks, Add stack, Repository, compose path `mcp/docker-compose.yml`): set `MCP_HOST` to the public host name, and have the server's HTTPS reverse proxy forward that name to port 3300. The rendered pictures are kept on a volume, so they survive a restart. The stack takes the image from `ghcr.io/iconem/terrain-viewer-mcp`, which a workflow ([`docker-publish.yml`](https://github.com/Iconem/terrain-viewer/blob/main/.github/workflows/docker-publish.yml)) rebuilds on each change of the server.

### The tile service

A second image, `ghcr.io/iconem/terrain-viewer-tiles`, serves what the app draws as map tiles and as pictures over plain HTTP. In the stack the MCP server takes its pictures from it (`TV_RENDER_URL`). Its addresses, parameters and a page to try them: [Tile service](/dev/tile-service).

The server's own notes, with the files and what was tested, are in [`mcp/README.md`](https://github.com/Iconem/terrain-viewer/blob/main/mcp/README.md).
