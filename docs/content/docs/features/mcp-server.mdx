It needs git, Node 20 or later, pnpm and Google Chrome on the computer. Claude runs the commands and asks before each one unless you allowed them. After the restart, ask in your own words; no tool has to be named.

The [skill](/features/ai-assistants) teaches an assistant to write a link. The server goes further: the assistant can look things up (where a place is, which datasets cover it, which dated images exist) and the result shows in the conversation.

## What you can ask

- "Show me the slope of the terrain around the Matterhorn in 3D."
- "I am looking for ancient earthworks in the forest of the Veluwe. Which elevation data is best there, and show it so they stand out."
- "Which satellite images exist over Antakya after the February 2023 earthquake? Show the most recent."
- "Compare the surface model and the ground model over Amsterdam."
- "How high is the Matterhorn above Zermatt, and how steep is the line between them?"
- "Give me a GeoTIFF of the elevation around Mont Blanc."

## Tools

| Tool | What it does |
|---|---|
| `open_view` | A place and modes, shown in the conversation, with the link that opens it |
| `compare_sources` | One place twice, side by side or as an overlay: two terrain datasets, or the imagery of two dates |
| `geocode` | A place name to coordinates (OpenStreetMap) |
| `datasets_covering` | The terrain datasets of the library that cover a point, finest first, and the imagery catalogs that have something there |
| `catalog_items` | Dated satellite and aerial images and old maps for an area, from the catalogs the [timeline](/features/historical-imagery) reads |
| `imagery_dates` | The capture dates of the built-in dated imagery at a place: Esri Wayback and Google Earth historical |
| `search_stac` | Items of any STAC API or static catalog over an area |
| `elevation` | The height of points, or a profile along a line, on one or several datasets |
| `export_geotiff` | The elevation of an area as a GeoTIFF file (32-bit float, EPSG:3857) |
| `screenshot` | A picture of a view, so the assistant can look at the terrain itself |

`elevation` and `export_geotiff` read tile datasets (Mapterhorn, AWS, Terrarium and Terrain-RGB pyramids). A dataset served as a COG, a WMS or a VRT is read by the app alone: the assistant opens it with `open_view`, and its [Download section](/features/export-and-share) exports it.

## By hand

```bash
git clone https://github.com/Iconem/terrain-viewer
cd terrain-viewer && pnpm install
cd mcp && pnpm install && pnpm build
```

Claude Desktop: Settings, Developer, Edit Config, then restart the app.

```json
{
  "mcpServers": {
    "terrain-viewer": { "command": "node", "args": ["/path/to/terrain-viewer/mcp/server.mjs", "--stdio"] }
  }
}
```

Claude Code:

```bash
claude mcp add terrain-viewer -- node /path/to/terrain-viewer/mcp/server.mjs --stdio
```

claude.ai and ChatGPT reach a server by its address, not on your computer: run `pnpm start` in `mcp` (it listens on `http://localhost:3300/mcp`), put it behind a public HTTPS address, and add that address as a custom connector.

## What shows in the conversation

Three displays, picked by what the view needs and what the host allows, with buttons to switch:

- **Interactive map**: a map drawn in the conversation itself, to pan, zoom and tilt. It draws hillshade, 3D terrain and satellite imagery on the tile datasets. A view that needs nothing else opens this way.
- **Exact picture**: the view with every mode asked for (slope, local relief model, sky-view factor, dated imagery, a split), rendered by the server in a few seconds. A view that needs the app's computed modes opens this way, with the interactive map one click away.
- **Live app**: the app itself, in its [embed layout](/features/embedding). Claude frames a website inside a conversation only for some connectors: never for a server that runs on your computer, and for a server reached by its address only after you allow the site, in organizations where the feature is on ([Claude's documentation](https://claude.com/docs/connectors/building/mcp-apps/embedded-sites)).

When Claude shows the live app depends on how the server reached it:

| Server | Live app in the conversation |
|---|---|
| In Claude's directory, Verified listing | Shown, when the listing allows the site |
| In Claude's directory, Community listing | Refused |
| Added by its address (custom connector) | Only after you allow the site in the conversation, and only in a limited set of organizations that Anthropic chooses, in the unified chat and Cowork experience |
| Running on your computer | Refused |

No setting in Claude adds a site to an allowed list. Tested on 2026-11-20 with a custom connector on a personal Max plan and on a team with the unified experience on: Claude refused the site both times without asking, and the picture and the interactive map were shown instead. The **?** button on the view says which display was picked and what Claude reported.

A fourth display, **App here (test)**, runs the app itself in the conversation without a frame: the view loads the app's script and styles from its address, which Claude allows for declared hosts. It needs no permission to frame a site. Being tested: it reads only the hosts the server declares (the tile datasets, the French LiDAR service, the dated imagery catalogs), so a dataset on another host stays blank there. The **?** line lists what the host let through.

### Getting a Verified listing

The only way to the framed live app for everyone is a Verified listing in Claude's directory. Not done; what it takes, from Anthropic's pages ([submission](https://claude.com/docs/connectors/building/submission), [review criteria](https://claude.com/docs/connectors/building/review-criteria)), read on 2026-11-20:

- **Where**: `claude.ai/directory/manage`, then Submit new, then MCP connector. Any paid Claude plan can submit.
- **A permanent `https://` address** for the server. A temporary tunnel does not qualify. The server runs a headless Chrome for the pictures, so it needs a container host (the `mcp/Dockerfile`), not a static site or a serverless function.
- **Every tool** with a title and a read-only or destructive hint, a name of 64 characters or fewer, and reading kept apart from writing. The tools already carry titles and hints.
- **Documentation** and a privacy policy address. No sign-in is accepted for public data, which is the case here.
- **Not accepted**: financial transactions, and AI generation of images, video or audio. The `screenshot` tool renders a map and generates nothing, but a reviewer may ask.
- **Review**: a submission is scanned and listed as Community by default, which still refuses the frame. Only some get the human review that leads to Verified, with no stated delay. Escalations: `mcp-review@anthropic.com`. The site to frame has to be named in the listing.

**Open in the browser** always opens the full app, at the place the interactive map was moved to.

The server's own notes, with the files and what was tested, are in [`mcp/README.md`](https://github.com/Iconem/terrain-viewer/blob/main/mcp/README.md).
