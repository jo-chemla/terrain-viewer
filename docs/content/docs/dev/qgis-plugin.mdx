title: QGIS Plugin (plan)
description: A QGIS plugin with the app's sidebar, in two steps - a panel that writes tile service layers, then the modes computed in Python with numpy - and Send2MapApp, the app's "Open in" list in QGIS.
---

Today QGIS gets the app's modes through the [tile service](/dev/tile-service): `/qgis.qgz` is a project with every mode as an XYZ layer, configured as a view was. A layer's settings live in its address, and QGIS has no control bound to an XYZ address's parameters: changing a ramp or a radius means editing the layer's source URL. A plugin is the way to have controls. Two steps, the first cheap.

## Step 1: a panel that writes tile service layers (done)

Written on 2026-11-23, in [`qgis-plugin/`](https://github.com/Iconem/terrain-viewer/tree/main/qgis-plugin). Checked headless in QGIS 4.2 and 3.44 LTR against a local tile service: the panel builds, a share link opens, the layers are valid and draw.

A dock panel laid out as the app's sidebar: the same groups (Elevation Hypso, Terrain Analysis, Relief Visualization, Hillshade, Lighting Effects, Overlays), each mode a checkbox with its opacity and settings (ramp, range, radius, method) behind a gear button, a terrain source picker, the keys, and the address of a tile service.

- Each checked mode is a layer of the project: an XYZ layer whose address the panel writes (`/terrain-tiles/{z}/{x}/{y}.png?modes=<mode>&<its settings>`), as `/qgis.qgz` does, in a "Terrain Viewer (live)" group with the app's panel groups, stacked as the map stacks them. A changed setting rewrites that layer's address and refreshes it; only the settings that differ from the app's defaults go into it. Opacity and blending stay QGIS layer settings (the tiles are asked opaque, the shading modes multiplied; see the QGIS section of the tile service page).
- The overlays (contours, iso-line, mound candidates, plane slicer, graticule) are raster layers as the app draws them, and on demand also vector tile layers (`.pbf`), styled by the plugin in the mode's colour.
- A mode computed as numbers has a "values" box: its values before the ramp, in natural units, as a Float32 raster GDAL reads from the service's `/gdal.xml` (see [values, not colours](/dev/tile-service#values-not-colours)), for QGIS's own analysis tools.
- The lists come from the service: `/sources` for the terrain sources, `/colorramps` for the ramps, and `/processes?expand=true`, each mode as an [OGC API - Processes](/dev/tile-service#ogc-api---processes) description: the panel's groups (`x-tv-groups`) and, for each mode, its form, whether it is shading, its opacity parameter (`x-tv-` properties) and its settings as inputs (the app's URL parameters, with type, allowed values and default, from the generated URL reference). A service older than 2026-11-24 has no `/processes` and is refused with a message to update it (0.2.2 dropped the fallback to the removed `/modes` and `/tiles`). So a new mode or parameter in the app reaches the plugin without a plugin release.
- "Open from link": paste a share link, get its layers. `/view?<the link's query>` answers what the view switches on, the opacities, the parameters every layer keeps and the camera (the reading `/qgis.qgz` does).
- **Freeze** copies the layers drawn now (the checked ones) into a new group under the live one, which stays on top, named with the date, the time and the place ("Frozen 2026-11-24 14:05 — 44.51, 4.00 z11"): XYZ, vector tile and values layers alike, every setting in their addresses, with their opacity, blending, style and order. The copies carry no mark the panel looks for, so later changes leave them as they are; several freezes stack as several groups, the newest on top, to compare settings side by side.
- A saved project reopens as it was: on Connect, the panel reads its layers' addresses back into its checkboxes and settings.
- Pure Python on QGIS's own API, no dependency. It needs a tile service: the [Terrain Viewer desktop app's](#with-the-desktop-app) (`http://localhost:3400`), the one inside the platform zips (below, when enabled), a local one (`cd tile-server && pnpm start`) or a hosted one.
- QGIS is a flat, north-up client that picks the tiles it loads: the plugin never asks for 3D, tilted, rotated or split views, so the service it talks to needs no browser.
- When the service does not answer (at Connect, or later: the panel asks its `/health` every 15 s in the background), the status line and QGIS's message bar say so. For an address on this machine (`localhost`, `127.0.0.1`) the warning suggests starting the desktop app with its tile service on (port of the address), or a local service, and, in a platform zip, checking **Local bundled tile service**; for a remote one, checking the address or the network.

### Install

The zips are on the [`qgis-plugins-2026-11-25b`](https://github.com/Iconem/terrain-viewer/releases/tag/qgis-plugins-2026-11-25b) release (Terrain Viewer 0.4.0, Send2MapApp 0.5.1), for QGIS 3.22 to 4.x (Terrain Viewer needs 3.28); 0.3.0 stays on [`qgis-plugins-2026-11-25`](https://github.com/Iconem/terrain-viewer/releases/tag/qgis-plugins-2026-11-25). Terrain Viewer comes in two variants, which install into the same folder and replace each other:

| Zip | Size | What it needs |
|---|---|---|
| `terrain_viewer-0.4.0.zip` (plain) | 20 KB | Pure Python. A tile service to connect to: the desktop app's (`http://localhost:3400`), a local one (`cd tile-server && pnpm start`) or a hosted one |
| `terrain_viewer-0.4.0-windows-x64.zip`, `-macos-arm64`, `-macos-x64`, `-linux-x64` (bundled) | 48 to 60 MB | Nothing else: the tile service is inside (`terrain_viewer/server/`: Node 22, the service, its node_modules with that platform's sharp binaries), off until enabled |
| `send2map_app-0.5.1.zip` | 30 KB | Pure Python, no service |

In QGIS: **Plugins > Manage and Install Plugins > Install from ZIP**, pick the zip, **Install Plugin**. The Terrain Viewer button is on the Web toolbar (or **Web > Terrain Viewer**). Not yet on plugins.qgis.org (its `metadata.txt` needs an `email` first); the bundled zips are for the release only: they carry a platform binary and are some 2,500 times the size of the plain one.

#### With the desktop app

The simplest local setup, with the plain zip: run the [Terrain Viewer desktop app](/features/advanced/desktop#local-tile-service), turn on **Settings > Desktop: local tile service** (port 3400 by default), then in QGIS open the Terrain Viewer panel with the address `http://localhost:3400` (the default) and press **Connect**. The desktop app runs the same service the platform zips carry, on this computer only, for as long as the app is open (and again at its next launch while the setting stays on). With another port, type `http://localhost:<port>` in the panel.

#### The bundled tile service

With a platform zip, the panel has a **Local bundled tile service** box, **off by default** (0.4.0; 0.3.0 had it on), so the service never runs unless asked for:

- Checking the box only enables it; **Connect** starts it. The panel opening (the toolbar button, a saved project) never starts it: with the box on, the status line says to press Connect. Unchecked, the panel connects to the address field, e.g. the desktop app's service.
- **Connect** starts it as a subprocess, `bin/node server.mjs` in `terrain_viewer/server/`, listening on this machine only (`127.0.0.1`), on port 3410 or, when that is taken, a free one; the address field shows it and the status line says where it runs and its process id. The first start takes about 3 s. A saved project's layers follow the port: on Connect their addresses are rewritten with the current one.
- It stops when the plugin unloads (QGIS quitting, the plugin disabled, reinstalled or updated) or the box is unchecked; and, if QGIS goes without stopping it (a crash), by itself: it is started with `TV_EXIT_WITH_STDIN=1` and stops when its standard input, a pipe from QGIS, closes. Its log is `terrain-viewer-qgis-tile-service.log` in the system's temporary folder; the status line names it when the service does not start.
- **Earthdata token** (optional, shown with the box): a NASA Earthdata token for G-LiHT's protected files, given to the service as `EARTHDATA_TOKEN` when it starts (changing it restarts the service). It is kept in QGIS's settings (`terrain_viewer/earthdataToken`), never in a layer's address, and no token ships in a zip; the service reads no `.env` (`TV_ENV_FILE` points at nothing).
- **No browser engine**: the bundled service draws what QGIS asks for, flat north-up tiles, with the direct engine (Node and sharp). playwright-core is not in the zip and the service runs with `TV_NO_BROWSER=1`, so it never looks for Chrome or Edge; a 3D, tilted, rotated or split view, or a source only the app draws, answers 501 with a message (0.3.0 shipped playwright-core and looked for Chrome, then Edge; leaving it out saves about 3 MB a zip).
- If it stops while connected (a crash, the process killed), the background health check warns, and Connect starts it again.
- QGIS's zip installer drops the executable bits on macOS and Linux: the plugin sets them on `bin/node` before starting it. The macOS Node is the one nodejs.org signs and notarizes; sharp's libraries come from its npm packages.

From the repository:

```bash
cd qgis-plugin
python make_zip.py                         # dist/terrain_viewer-0.4.0.zip and dist/send2map_app-0.5.1.zip
python make_zip.py --bundled windows-x64   # dist/terrain_viewer-0.4.0-windows-x64.zip (any platform from any host; none named: all four)
python make_zip.py --server-dir windows-x64 <folder>   # the service alone, as the desktop app ships it
python smoke_bundled.py dist/terrain_viewer-0.4.0-windows-x64.zip              # starts its service as the plugin does, asks a tile, stops it (no QGIS)
# Through the panel, in headless QGIS, from a temporary plugins folder: Connect, processes, a slope layer, a tile,
# the unresponsive warnings (a dead local address, the service going away while connected)
QT_QPA_PLATFORM=offscreen python-qgis test_service_paths.py bundled dist/terrain_viewer-0.4.0-windows-x64.zip
QT_QPA_PLATFORM=offscreen python-qgis test_service_paths.py external dist/terrain_viewer-0.4.0.zip http://localhost:3400 [--stop "<command>"]
```

`--bundled` needs the root install and tile-server's (`tile-server/build.mjs` bundles the app's code into `generated/` first). It takes Node 22.22.3 from nodejs.org, checked against its `SHASUMS256.txt`, and installs tile-server's production dependencies flat (`node-linker=hoisted`: a zip keeps no symlinks) with pnpm's `supportedArchitectures` set to the platform, so the right `@img/sharp-*` binaries land; source maps, type declarations and playwright-core are left out. The [QGIS plugins workflow](https://github.com/Iconem/terrain-viewer/actions/workflows/qgis-plugins.yml) (`.github/workflows/qgis-plugins.yml`, on demand) builds each platform on its own runner, starts its service there with `smoke_bundled.py`, and with `release_tag` attaches all the zips to a release.

## Send2MapApp: "Open in"

A second plugin in the same folder, [`qgis-plugin/send2map_app/`](https://github.com/Iconem/terrain-viewer/tree/main/qgis-plugin/send2map_app): the place shown or clicked in QGIS opened in another viewer at the same place and scale, from a dropdown on the Web toolbar (the current view, in the destination picked, which is remembered), the button itself (a map tool: the point clicked), the map canvas's right-click menu ("Open in" at the point clicked) or **Web > Send2MapApp**. QGIS 3.22 to 4.x; install it from the [`qgis-plugins-2026-11-25`](https://github.com/Iconem/terrain-viewer/releases/tag/qgis-plugins-2026-11-25) release as above.

- **A QGIS map tool**: the button is checked while the tool is on, with a crosshair cursor carrying an "open elsewhere" badge, and unchecks itself when another map tool (Pan, Identify, ...) is picked, as QGIS's own tools do. The destination picked is kept in QGIS's settings (`plugins/send2map_app/destination`).
- **Icons**: QGIS-style SVGs for the plugin, Terrain Viewer and the web viewers, QGIS's own 3D globe for Google Maps 3D and Bing Maps 3D, the publishers' logos for Google Earth, Esri, Maxar and Search-EO.

- **Destinations**: every entry of the app's own "Open in" list (Iconem River-REM, Iconem Search-EO, ESRI Wayback, Google Maps 3D, Google Earth historical and 3D on the web, Bing Maps 3D, ShadeMap, LiDAR Lens, BBBike MapCompare), plus Terrain Viewer itself and its historical mode (historical-satellite.iconem.com), Maxar, and Google Earth Pro on the desktop through a KML file. LiDAR Lens is greyed out outside Britain and Ireland, as in the app.
- **The camera**: the canvas centre or the point clicked, the zoom whose 512 px tiles have the canvas's ground resolution there (the app's zoom, so the other viewer opens at the same scale in any project CRS), the heading from the canvas rotation.
- **One list**: the app's destinations are a Python port of `OPEN_IN_DESTINATIONS` (`components/TerrainControlPanel/open-in-links.tsx`). `python qgis-plugin/test_open_in.py` evaluates the TypeScript builders under Node and compares ids, labels, coverage and URLs for a set of cameras, so a destination added to the app fails the test until the plugin has it.
- **Lineage and licence**: it began as [Send2GE (`send2google_earth`)](https://plugins.qgis.org/plugins/send2google_earth/) by Maxim Dubinin and NextGIS ([source](https://github.com/nextgis/qgis_send2google_earth)), a map tool that sends the point clicked to Google Earth through a KML file. Iconem's additions in 2025 (as Send2MapApp: web destinations in a toolbar dropdown) and 2026 (the app's whole list, the right-click menu, the current view, QGIS 4) keep its licence, the GNU GPL v2 or later, and its copyright lines; that is why it is a plugin of its own rather than part of the MIT `terrain_viewer`.

## Step 2: the modes computed in QGIS

The same panel with no tile service: the modes computed in Python, on the elevation the plugin reads.

- **Reading:** GDAL reads the tiles and nothing else. A Terrarium or Terrain-RGB pyramid through GDAL's WMS/TMS driver (the XML of `gdalTileSource` in `lib/terrain-tile-spec.ts`), a COG or VRT directly, a raw WMS through GDAL's WMS driver. Decoding the RGB packing into metres is numpy (the formulas of `lib/elevation-encoding.ts`). The sources only the app's protocols read (LERC, quantized mesh, GEM-15's cells, a difference) need their own reader or stay on step 1.
- **Computing:** numpy, not `gdaldem`: the app's modes are its own (LRM, sky view factor, openness, matcap, Phong, the mound detector, the eigen-based ones), and the point is that QGIS shows what the app shows. Each `lib/*-protocol.ts` is a kernel over an elevation grid with a margin, which ports to numpy array code: slope, aspect, curvature, TPI, TRI and roughness in a few lines each; sky view factor and openness as the app's ray sweeps (vectorised per direction); matcap and Phong as the shaders' formulas per pixel; the colour ramps from `lib/color-ramps.ts`.
- **Delivery:** a QGIS raster layer per mode, computed for the canvas extent at the canvas resolution and recomputed on pan and zoom (debounced, in a background task), or written to a GeoTIFF on request. Optionally a Processing provider, so each mode is also an algorithm for models and batch runs.
- **Checking:** the port is checked against the app tile by tile, as `tile-server/compare-engines.mjs` checks the direct engine against the browser: same tiles, a table of differences.
- **Keeping in step:** two implementations of each mode drift. The comparison above runs in CI on a fixed set of tiles, so a change to a protocol that the Python port does not follow fails a check.

A first experiment (2026-11-25) ported hillshade, sky view factor and the shadow sweep to numpy and timed them in QGIS: [QGIS Live Compute](/dev/qgis-live-compute).

Weeks of work, mode by mode; step 1 stays useful as the fallback for any mode not ported yet.
