# Static indexes: what to prebuild, where to keep it (survey of 2026-11-13)

- **Repo weight.** Pack 383 MB. The weight is docs/public/screenshots (173 MB, 4K jpg plus a 9 MB mp4), not data indexes: public/vrt is 2.8 MB (the two Open Buildings sample VRTs), public/coverage 5.8 MB. A release-asset move only pays for the screenshots (the docs build would download them like the deploy does for ux-flows).
- **GEM-15**: no index needed, the cell address follows from the coordinates and the STAC item per cell is fetched on demand (see [[gcs-cors-media-endpoint]]).
- **Open Buildings 2.5D, whole earth per year**: 1 173 manifests (39 S2 cells x 73 UTM zones x 8 years, about 950 KB each) on the bucket, CORS through the media endpoint. One VRT per manifest is what docs/scripts/build-open-buildings-vrt.mjs writes; the whole earth cannot be one VRT (mixed UTM zones) and does not need hosting: a committed index of manifest name -> lon/lat bbox (about 40 KB, computed once from each manifest's affineTransform and dimensions) plus an `openbuildings://<year>` router that fetches the 1-2 manifests a tile touches and builds the VrtDoc in memory, the gem15 pattern. About a day. Not built.
- **OpenTopography global VRTs** (added to the library 2026-11-13 as in-browser vrt entries): COP30/COP30_hh.vrt, COP90/COP90_hh.vrt, NASADEM/NASADEM_be.vrt, SRTM_GL1/SRTM_GL1_srtm.vrt, SRTM_GL3/SRTM_GL3_srtm.vrt, EU_DTM/EU_DTM_be.vrt, GEDTM30/GEDTM30_be.vrt, SRTM15Plus/SRTM15Plus_srtm.vrt (same host and CORS as AW3D30, so a "type": "vrt" entry each). GEBCO has none.
- **Scotland**: done 2026-11-13 the hosted way: four VRTs (dtm/dsm, with and without the no-overview files) built by docs/scripts/build-scotland-vrt.mjs from 9 600 headers a product, uploaded to the `dataset-indexes` release on Iconem/terrain-viewer, copied into dist/vrt/ by the deploy (release assets send no CORS header; the site does). Phase-1 files are irregular strips without overviews; Orkney 2023 has none either. The Open Buildings router replaced the committed sample VRTs (public/vrt/ is now gitignored, used only for local tests).
- **The 3dtiled precedent**: the France IGN LiDAR HD virtual point cloud is a STAC ItemCollection of 337 206 COPC items, 29 MB split into 564 quadkey children, published as the `sample-assets-v1` GitHub release on jo-chemla/3dtiled-to-3dtiles and read by the tile server from there; the overview COPC is the host's own file. That is the shape for any index too big to commit: build once, release asset, fetch at deploy or at runtime.
- **Docs media moved 2026-11-13**: docs/public/screenshots is gitignored; `docs/media.lock` pins `screenshots-<sha12>.tar` on the `docs-media` release (Iconem/terrain-viewer); `scripts/docs-media.mjs pull|push|status`; pull runs before `pnpm app`, docs dev/build and the slide scripts (strict in builds). History was NOT rewritten (Jonathan: not yet). After a capture: `pnpm docs:media:push` and commit the lock.
- **CRS lookup order in lib/vrt-protocol.ts**: KNOWN_SRS table (Helmert shifts), UTM by code, `@developmentseed/epsg` (all EPSG as WKT2, 309 KB, bundled, offline), epsg.io last. proj4js reads the WKT2 and knows OSGB36 by name; RD New (28992) is 169 m off without its towgs84, hence the table.
- **GEM-15 DSM** reads in-browser by default since 2026-11-13 (Jonathan: titiler is the user's call): `buildVrtUrl(url, viaTitiler)` appends `#titiler` for gem15 URLs when the source or the global setting says titiler. COP90 and SRTM GL3 were removed from the library (coarser duplicates).
- **Docs media on another machine**: pull is a public download, no login, and runs by itself before `pnpm app` / `pnpm docs` / builds. Push needs `gh` with write access to Iconem/terrain-viewer; the retake only reaches other machines and the deploy once `docs/media.lock` is committed and pushed. An unpushed retake is LOST if a `git pull` brings a different lock (pull replaces the folder): push before pulling. Clones older than 2026-11-13 see the screenshots deleted on their next pull, then restored by the first `pnpm app` or `pnpm docs`. Tar, not zip: nothing to compress, `tar` is everywhere with no dependency.
- **Release inventory** lives in docs/content/docs/dev/releases.mdx (desktop-latest, desktop-latest-light, desktop-v<version>, dataset-indexes, docs-media, slides-<date>, demo-takes, ux-flows). GitHub orders the releases page by tag date; no hiding short of delete or draft. Latest badge belongs to `desktop-latest`: create any other release with `--latest=false` (dataset-indexes stole it on 2026-11-13, fixed by `gh release edit desktop-latest --latest`). Non-software releases are prereleases.
- **Release titles carry a kind prefix** since 2026-11-13 (Jonathan's ask): `Desktop: ...`, `Data: ...`, `Media: ...`, set in desktop.yml, ux-flows-capture.yml and scripts/docs-media.mjs. Old `desktop-v<version>` releases are deleted (with their tags) once no winget manifest points at them; only the current one stays.
- **Tag naming** (2026-11-13, Jonathan): rolling stores have a bare name (`ux-flows`, `demo-takes`, `docs-media`), `dataset-indexes` too (was datasets-v1, briefly dated; Jonathan chose bare so a rebuild needs no workflow edit); only `slides-2026-10-05` is dated. UX flows are not versioned yet (comparing captures across viewer versions is a possible later use). `desktop-latest` and `desktop-latest-light` must NOT be renamed: the updater feed URL is baked into installed apps.
- **Coverage GeoJSONs and VRTs through one lock** (2026-11-13): `datasets.lock.json` + `scripts/dataset-assets.mjs pull|push|status`; files on the `dataset-indexes` release, untracked in public/coverage and public/vrt; pull runs in `pnpm app` and strictly in `pnpm build` (so deploy and desktop get them; the deploy workflow's own download step was removed). Pull keeps a locally changed file (hash of the last pull in .cache/dataset-assets.json). The desktop docs link now points at the `desktop-latest` release page, no version to bump.
