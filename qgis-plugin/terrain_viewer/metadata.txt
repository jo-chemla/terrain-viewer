about=A dock panel with the groups of Terrain Viewer's sidebar, one modes tree whatever draws it. Pick a backend at the top (radio buttons): Python backend (the modes computed in QGIS itself with numpy, no service, started when picked: every mode, from tile pyramids, COGs, VRTs, raw WMS and WCS, QGIS raster layers and anything GDAL opens), Packaged tile server (the Terrain Viewer tile service packaged for QGIS, Node and the service, about 50 MB, downloaded from the project's GitHub release the first time, its sha256 checked, started on this machine when you connect, stopped with QGIS), or Remote tile server (an address: the Terrain Viewer desktop app's, http://localhost:3400, one you run, or a hosted one). Each checked mode becomes a layer, with its settings in the layer's address; changing a setting rewrites the address. Each row has its opacity and its forms: Color (or Raster), Values (a Float32 raster for Identify, the raster calculator, Processing) and, for the overlays, Vector (vector tiles, the default). Sliders with number boxes, ramp and matcap selects with previews, a light direction pad shared by the shaded modes (free, or the sun at a date and time over the map's centre), contour labels, symmetric ramps, the source picker in groups (the project's elevation layers, the worldwide defaults, the terrain library) with a zoom to the source and the raw elevation of a library COG, VRT or WMS added as a QGIS layer, API keys behind a key. "Open link" loads the layers of a share link (or its query). "Freeze" copies the layers drawn now into a group the panel never changes, to compare settings. Updates: add the plugin repository https://github.com/Iconem/terrain-viewer/releases/download/qgis-plugins-repository/plugins.xml in the plugin manager's settings, or press Update in the panel when it says a newer version is out. The panel is built from what the service answers, so new modes and settings appear without a plugin update. Pure Python, no dependency.

changelog=0.9.1
    * Blobness orientation is now the direction a feature runs (north-south 0, east-west 90), with a cyclic ramp, as in the web app; the bundled tile service rebuilt with it.
    0.9.0
    * Updates without plugins.qgis.org: each release attaches a QGIS plugin repository (plugins.xml, also at the fixed address https://github.com/Iconem/terrain-viewer/releases/download/qgis-plugins-repository/plugins.xml: add it once in Plugins > Manage and Install Plugins > Settings, and tick "Show also experimental plugins"); and the panel looks for a newer version once a day and offers "Update to x.y.z" (downloaded from the release, its sha256 checked, installed over this version, the plugin reloaded)
    * The first mode checked in a fresh, empty project sets it up as QGIS would (EPSG:3857, the whole world); after every mode was unchecked, the next one keeps the canvas where it is (0.8.0 kept it every time)
    * A mode's opacity is a small slider in its row, between its name and its forms (it was under the cog)
    * The panel's order: Hillshade above Elevation Hypso; the overlays' group is "Vector overlays": Contours, Iso-line, Plane slicer, Graticule, Mound candidates (the layer tree keeps the map's stacking)
    * Backends in the order Python backend, Packaged tile server, Remote tile server; a new user starts on the Python backend (users of a tile server keep theirs)
    * The light pad: the shaded layers follow it while it is dragged, the first move at once, then a new light as soon as the canvas has drawn the last (0.8.0: nothing until half a second after the last move); the Python backend's hillshade is shaded in float32 (faster, the same picture)
    * The Python backend's server no longer shares its port with another QGIS on Windows (the second one's tiles were answered by the first: "unknown source")
    * Python backend: the library's COGs and VRTs (/vsicurl/), raw WMS (a GDAL WMS description, Float32) and raw WCS and ArcGIS image services (the app's bounding box requests) are read, among them France's IGN LiDAR HD and Canada's NRCan MRDEM; a source it cannot read draws nothing with a warning (0.8.0 drew Mapterhorn in its place, the whole world's hillshade)
    * The source picker in groups: QGIS elevation layers (single band, float or 16-bit integers), Worldwide defaults, Terrain library; a button adds a library COG, VRT or WMS as a QGIS layer in "Raw elevation inputs" (the source the Python backend reads)
    * Labels: only the contours keep theirs, at half the size (4.25 pt in a 0.5 mm buffer); none on the iso-line, plane slicer and graticule
    * The tile service's old /sources address is gone: the panel asks /terrain-sources only
  0.8.0
    * Backends as radio buttons in a row, renamed Packaged tile server, Remote tile server and Python backend; the Python backend has no Connect button: it starts when picked (and when the panel opens with it picked)
    * Light: besides the free pad, "Sun at a date and time": a date and time picker (UTC), a day of year slider and an hour slider set the azimuth and elevation to the sun's over the map's centre (the app's solar model, lib/solar-position.ts, ported and tested against it); the pad shows the result, dragging it goes back to Free
    * The canvas stays where it is: with every mode unchecked and no other layer, the next mode checked zoomed QGIS out to the whole world (QGIS's first-layer setup), now kept off for the panel's layers
    * Labels: contours (major lines), iso-lines, plane slicer and graticule carry their values as QGIS labels, on by default, black text in a white buffer, placed by QGIS; no point symbols on the overlays' vector tiles (kept for the mound detector's tells)
    * A pointing hand (and a light background on a mode's line) over what takes a click: rows, boxes, cogs, group titles, folds, buttons
    * Color, not Colour, everywhere in the panel
    * Switching backend could drop a checked mode's layer (a row of the tree before the switch, still scheduled, removed it)
  0.7.0
    * Three backends picked at the top of the panel, each with its options: Local service (installed on first Connect, then started), Remote service (an address), Python (experimental). Connect works for each (0.6.0's Connect did nothing while "Local tile service" was checked: the button's checked argument read as "do not start")
    * One modes tree for every backend: under Python, the modes it does not compute are greyed out with a note, the settings it ignores too, and Values shows only for modes that have values. The tree is there before connecting (a snapshot packaged with the plugin)
    * Python backend: 24 of the 25 modes (new: shape index, blobness, eigen ratio, orientation, local dominance, building shadows, iso-line, plane slicer, graticule), every vector form (contours, iso-lines, graticule lines, plane slicer areas) as a layer recomputed for the view; only the mound detector needs a tile service
    * A click anywhere on a mode's line toggles it; overlays default to vector tiles, the Vector box left of Raster
    * Sliders with number boxes for every numeric setting; color ramp and matcap selects with previews packaged in the plugin; symmetric ramps mirror the minimum live (read only); a light pad (azimuth by angle, elevation by distance) and its sliders, shared by hillshade, Phong and the shadows
    * Unchecking the last mode of a group removes the empty group (and the live group when nothing is left); unchecking removes every layer of the mode, a duplicated one included
    * Zoom to the source's bounds; API keys (Mapbox, MapTiler, HERE, Google, Cesium ion) folded behind a key; the Python backend follows the source picked (Terrarium and Terrain-RGB tiles, Mapbox and MapTiler with their keys)
    * Open link: a whole share link or its bare query; the backend is checked first (one message, not a timeout per tile); the link's source is kept (an id the list lacks is added instead of being ignored) and the app's own parameters (splitRatio, the camera) stay out of the tile addresses
  0.6.0
    * Each mode row: its checkbox on the left, Color and Values on the right (and Vector for the overlays). Checking a mode turns on its colored layer; either form or both can be picked; the settings cog shows while Color is on. Unchecking removes the layers (they used to be hidden), and a layer removed by hand unchecks its box
    * Local compute: the same rows (Color: colored tiles with QGIS's ramps; Values: Float32 for Identify), plus Phong and matcap (the app's matcap pictures) (both match the tile service at 100 %), and contour lines as a vector layer recomputed for the view
    * Values layers are resampled early (GDAL, bilinear) so they no longer show blocky pixels between zoom levels; a style, opacity or resampling set in a layer's properties is kept when a setting rewrites its address
    * No Earthdata token in the plugin: a token lives in the tile service's environment only (the local service started from the panel inherits QGIS's EARTHDATA_TOKEN)
  0.5.0
    * One plain plugin: "Install local tile service" downloads the tile service of this platform from the GitHub release this version pins (sha256 checked) into the plugin's data folder; "Remove" deletes it. Replaces the four 50 MB platform zips
    * Experimental local compute, now at the top of the panel: 14 modes (elevation as hypsometric tint, hillshade, multidirectional hillshade, slope, aspect, curvature in six forms, TPI, TRI, roughness, local relief model, sky view factor, openness positive and negative, shadows, a contour mask), checked against the tile service and gdaldem
    * Local compute as values: Float32 layers read by GDAL from the plugin's localhost server, drawn with QGIS's color ramps (a colored default per mode), Identify and the raster calculator read the numbers; grey image tiles remain an option
    * The localhost server computes on a pool sized to the cores and keeps finished tiles: a 1920x1080 canvas draws in 0.2 to 0.5 s once the elevation is cached (1 to 1.5 s before)
  0.4.0
    * The bundled tile service is off by default: checking "Local bundled tile service" enables it and Connect starts it; the panel opening never does
    * No browser engine in the platform zips (no playwright-core, no Chrome or Edge looked for): QGIS asks for flat tiles only; about 3 MB smaller
    * A tile service that does not answer, at Connect or later (checked every 15 s), is warned about in the panel and the message bar; for a local address the warning suggests the Terrain Viewer desktop app's tile service (or the bundled one)
  0.3.0
    * Platform zips (Windows x64, macOS arm64 and x64, Linux x64) carry the tile service: "Local bundled tile service" starts it on this machine when the panel connects, stops it when QGIS quits; an optional Earthdata token for it
    * The plain zip is unchanged: pure Python, a tile service to connect to

    * The button sits on the Web toolbar, with an SVG icon
