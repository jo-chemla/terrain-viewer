description=Terrain Viewer's modes (slope, sky view factor, openness, matcap, contours...) as QGIS layers, set from a panel like the app's sidebar.
about=A dock panel with the groups of Terrain Viewer's sidebar. Each checked mode becomes an XYZ layer of a Terrain Viewer tile service (the Terrain Viewer desktop app's, Settings > Desktop: local tile service, on http://localhost:3400; one installed from the panel, off until enabled; a local one: cd tile-server && pnpm start; or a hosted one), with its settings in the layer's address; changing a setting rewrites the address. The overlays (contours, iso-line, mound candidates, plane slicer, graticule) can also be loaded as vector tiles. "Open from link" loads the layers of a share link. "Freeze" copies the layers drawn now into a group the panel never changes, to compare settings. The panel is built from what the service answers, so new modes and settings appear without a plugin update. The plugin is pure Python, no dependency: "Install local tile service" downloads the tile service of your platform (Node and the service, about 50 MB) from the project's GitHub release, the version this plugin pins, its sha256 checked. Each mode row has its own Colour and Values boxes: the coloured layer, the numbers (a Float32 raster for Identify, the raster calculator, Processing), or both. Experimental, at the top of the panel: 16 terrain modes computed in QGIS itself with numpy (hillshade, multidirectional hillshade, slope, aspect, curvature, TPI, TRI, roughness, local relief model, sky view factor, openness, shadows, Phong, matcap, contours as a mask and as lines, hypsometric tint), no tile service, as coloured tiles or Float32 layers styled with QGIS's own colour ramps. A service that does not answer is warned about in the panel and the message bar.

changelog=0.6.0
    * Each mode row: its checkbox on the left, Colour and Values on the right (and Vector for the overlays). Checking a mode turns on its coloured layer; either form or both can be picked; the settings cog shows while Colour is on. Unchecking removes the layers (they used to be hidden), and a layer removed by hand unchecks its box
    * Local compute: the same rows (Colour: coloured tiles with QGIS's ramps; Values: Float32 for Identify), plus Phong and matcap (the app's matcap pictures) (both match the tile service at 100 %), and contour lines as a vector layer recomputed for the view
    * Values layers are resampled early (GDAL, bilinear) so they no longer show blocky pixels between zoom levels; a style, opacity or resampling set in a layer's properties is kept when a setting rewrites its address
    * No Earthdata token in the plugin: a token lives in the tile service's environment only (the local service started from the panel inherits QGIS's EARTHDATA_TOKEN)
  0.5.0
    * One plain plugin: "Install local tile service" downloads the tile service of this platform from the GitHub release this version pins (sha256 checked) into the plugin's data folder; "Remove" deletes it. Replaces the four 50 MB platform zips
    * Experimental local compute, now at the top of the panel: 14 modes (elevation as hypsometric tint, hillshade, multidirectional hillshade, slope, aspect, curvature in six forms, TPI, TRI, roughness, local relief model, sky view factor, openness positive and negative, shadows, a contour mask), checked against the tile service and gdaldem
    * Local compute as values: Float32 layers read by GDAL from the plugin's localhost server, drawn with QGIS's colour ramps (a coloured default per mode), Identify and the raster calculator read the numbers; grey image tiles remain an option
    * The localhost server computes on a pool sized to the cores and keeps finished tiles: a 1920x1080 canvas draws in 0.2 to 0.5 s once the elevation is cached (1 to 1.5 s before)
  0.4.0
    * The bundled tile service is off by default: checking "Local bundled tile service" enables it and Connect starts it; the panel opening never does
    * No browser engine in the platform zips (no playwright-core, no Chrome or Edge looked for): QGIS asks for flat tiles only; about 3 MB smaller
    * A tile service that does not answer, at Connect or later (checked every 15 s), is warned about in the panel and the message bar; for a local address the warning suggests the Terrain Viewer desktop app's tile service (or the bundled one)
  0.3.0
    * Platform zips (Windows x64, macOS arm64 and x64, Linux x64) carry the tile service: "Local bundled tile service" starts it on this machine when the panel connects, stops it when QGIS quits; an optional Earthdata token for it
    * The plain zip is unchanged: pure Python, a tile service to connect to
  0.2.2
    * Needs a tile service from 2026-11-24 or later: the fallback to the removed /modes and /tiles addresses is gone
    * The button sits on the Web toolbar, with an SVG icon
  0.2.1
    * The live group is "Terrain Viewer (live)"; frozen groups carry the date
  0.2.0
    * Freeze: copy the layers drawn now into a group the panel never changes
